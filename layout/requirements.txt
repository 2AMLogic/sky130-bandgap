# Pinned klayout-tools (`klt`) install for layout/'s DRC/LVS flow (issue #14).
#
# klt v0.1.0 on PyPI (https://pypi.org/project/klayout-tools) ships only
# the `layers`/`stats`/`cells`/`drc`/`pdk` verbs -- `extract`, `lvs`, and
# `gen` (all required by this flow) are documented but not yet released
# there. The upstream README's own "Install" section names installing
# from source as the sanctioned way to get the latest development verbs:
#
#   uv tool install git+https://github.com/2AMLogic/klayout-tools
#
# This pins an exact commit rather than floating `main`, for the same
# reproducibility discipline sim/pdk.json applies to the PDK version: a
# re-run months from now installs the identical `klt` build instead of
# whatever `main` has drifted to. Bump this pin deliberately (and re-run
# layout/bin/run-trivial-cell-flow.sh to refresh the checked-in reports)
# when picking up new `klt` capability.
#
# Bumped for issue #15 (bandgap-core floorplan): the prior pin
# (0cd630886e7b0034671d3e1e5d3131150596275f) only supports
# `gen-compose`'s `placement.strategy: "row"`, which cannot express a real
# two-dimensional floorplan (2AMLogic/klayout-tools#321). This pin adds
# `placement.strategy: "explicit"` (2AMLogic/klayout-tools#330) plus a
# `gen-compose` request-path fix (#328/#332) and byte-reproducible GDS2
# output (#325) -- all additive, no behavior change to the row strategy or
# to `gen`/`drc`/`extract`/`lvs`, confirmed by re-running
# layout/bin/run-trivial-cell-flow.sh unmodified after the bump (still
# PASS, identical verdict; see trivial-cell/reports/ for the refreshed
# record).
#
# Bumped for issue #62 (routed bandgap-core layout). The prior pin
# (67ae02ed6199c0d9c314771669fbbc925364587a) predates three capabilities this
# issue's flow depends on, all now merged upstream:
#
#   * `res_array`'s `rows` fold parameter (2AMLogic/klayout-tools#415, merged
#     via #418) -- the reason the #15 skeleton drew a reduced 16-unit R2A/R2B
#     ladder instead of the real 108. With folding, 108 units occupy ~1,231
#     um^2 instead of a ~710 um-long single row, and the real count fits the
#     area budget. This is what closes issue #62's acceptance criterion 2.
#   * the `diff_pair` nfet/pfet misclassification fix (#421, merged via #426)
#     -- before it, every `flavor: "nfet"` device was enclosed in the
#     guard-ring well tie and extracted as `pfet`. Verified effective at this
#     pin: an isolated nfet `diff_pair` now extracts `{"nfet": 8}`, and the
#     composed layout reports both flavours.
#   * the `res_array` resistor-ID marker fix (#369, merged via #382) -- a
#     drawn ladder now extracts as `res_generic_po` resistors rather than
#     plain interconnect.
#
# It also carries `klt gen-compose`'s two-pin routing, `connectivity[]` net
# labels and `pins[]` pin promotion, which is what lets the routed flow draw
# real inter-block metal and promote named top-level pins.
#

# record).
# Bumped again for issue #62's LVS-closure increment. The prior pin
# (680ee42edf2319aa944f66df1f6f7db3975a73c4) predates the three upstream
# fixes for the friction PR #64 filed while building the routed layout:
#
#   * 2AMLogic/klayout-tools#432 -> merged via #440. `klt gen bjt_array` now
#     draws sky130's bipolar device-recognition marker (82/44) and a well tap
#     per unit device itself, so a `bjt_array` output extracts as `pnp`
#     without help. This retires the local `klt draw` marker/tap overlay PR
#     #64 had to compose -- the overlay is deleted here, not merely disabled,
#     and the PNP count is re-measured from the generator's own geometry.
#   * 2AMLogic/klayout-tools#433 -> merged via #439. `gen-compose` no longer
#     certifies a self-net route that crosses another pad on the same block:
#     it reports the net unroutable instead of silently drawing a short. This
#     makes the "bus an array's units" failure mode *visible*, but it does
#     NOT make bussing expressible -- upstream deliberately shipped the
#     fail-visibly option only, leaving "expose a second routing metal + via
#     role" and "via-drop routing" as follow-ups (see #439's own summary).
#     `_PDK_ROLE_LAYERS["sky130"]` at this pin still has exactly one `metal`
#     role (li1 67/20) and no via role. See gen_bandgap_routed.py's
#     MET1_OVERLAY_NOTE for what this flow does about that.
#   * 2AMLogic/klayout-tools#434 -> merged via #441. `guard_ring`/`diff_pair`/
#     `bjt_array` accept `ring_gap_side`/`ring_gap_um`/`ring_gap_offset_um`,
#     cutting one routing opening through a ring band and reporting it as a
#     `GAP_<side>` port the router may cross. This fires the explicit revert
#     trigger layout/matching-plan.md Section 5a recorded: the per-matched-
#     group guard/collector rings PR #64 had to switch off are switched back
#     on here.

# Bumped again for issue #62's post-#461 increment. The prior pin
# (6967be2d2c387b38243331ddfcc9d3495fa0bdb7) predates every upstream fix for
# the blockers the last three routed-flow records named. All five have now
# closed:
#
#   * 2AMLogic/klayout-tools#461 -> merged via #474. THE dominant blocker.
#     Every `klt gen` MOS generator used to draw the gate poly with exactly
#     the active region's extent, so the reported gate port sat on the shared
#     poly/diff boundary and no contact could be placed there legally (it
#     either straddled the diff edge or landed on poly over the channel).
#     `diff_pair`/`mos_array` now extend the poly past the diffusion into a
#     landing pad and report the gate port on the pad, so a gate is
#     contactable. This is what unblocks the six schematic nodes that
#     terminate on a gate (`VA`, `VB`, `D1`, `D2`, `GDRV`, `PN`), MOS finger
#     bussing, and therefore `devices.matched` moving off 0.
#   * 2AMLogic/klayout-tools#462 -> merged via #471. The dummy-device marker
#     suppression path was MOS-gate-only; it now covers resistors and
#     bipolars too. Measured at this pin: it changes nothing here, because
#     the path keys off `ExtractionDeck.dummy` and the sky130 curated deck
#     declares no such layer, no generator draws one, and `klt extract`
#     exposes no override. Filed as the remaining half, #491.
#   * 2AMLogic/klayout-tools#463 -> merged via #475. `gen res_array` on
#     sky130 could only draw the base `res_generic_po` flavour, while the
#     same tool's sky130 extraction deck recognises three. The schematic is
#     built on `res_high_po`; the layout draws it from this pin on, which is
#     what makes the resistor blocks a matching device class. It does NOT
#     give them a reachable bulk pad: the deck marks `res_high_po`
#     `bulk_to_substrate` and ties that terminal to its synthesized `vsubs`
#     global, which no drawn shape can join (filed as #490).
#   * 2AMLogic/klayout-tools#454 -> merged via #468. `gen-compose` now
#     exposes metal2/via1 routing roles with via-drop bussing, i.e. a second
#     routing metal above the layer every generator draws its pads on. This
#     is the capability whose absence forced this repo to hand-draw its own
#     met1 overlay (`layout/bin/met1_bus.py`, MET1_BUS_NOTE).
#   * 2AMLogic/klayout-tools#470 -> merged via #481. `klt extract` now
#     detects and reports multi-label net collisions instead of silently
#     emitting a merged `A|B` net name. The flow's own label-collision gate
#     stays in place (it is cheap and it is what caught the original), but
#     the upstream silence this issue filed against is fixed.
#
# Also carried, and relevant to this flow: #467/#472 (self-net short and
# drawn-pad-crossing detection hardening in `gen-compose`) and #477 (`klt
# lvs` degrades gracefully instead of crashing when `combine_devices()`
# raises a partial-match `RuntimeError` -- the crash this flow previously
# had to catch and fall back from itself, filed as #466).
#
# Non-regression proof for the bump, same discipline as every pin above:

# identical four-way verdict (see trivial-cell/reports/ for the refreshed
# record), and layout/bin/run-bandgap-routed-flow.sh re-run produces the
# record this increment ships. One measured difference is expected and is
# #474 itself: every MOS cell is 0.42 um taller, because the gate poly now
# extends past the diffusion into its contact landing pad (the trivial cell's
# bbox y1 goes 1.24 -> 2.08 um). Nothing else in either record moves that is
# not this increment's own doing.
