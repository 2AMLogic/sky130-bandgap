# Pinned klayout-tools (`klt`) install for layout/'s DRC/LVS flow (issue #14).
#
# klt v0.1.0 on PyPI (https://pypi.org/project/klayout-tools) ships only
# the `layers`/`stats`/`cells`/`drc`/`pdk` verbs -- `extract`, `lvs`, and
# `gen` (all required by this flow) are documented but not yet released
# there. The upstream README's own "Install" section names installing
# from source as the sanctioned way to get the latest development verbs:
#
#   uv tool install git+https://github.com/2AMLogic/klayout-tools
#
# This pins an exact commit rather than floating `main`, for the same
# reproducibility discipline sim/pdk.json applies to the PDK version: a
# re-run months from now installs the identical `klt` build instead of
# whatever `main` has drifted to. Bump this pin deliberately (and re-run
# layout/bin/run-trivial-cell-flow.sh to refresh the checked-in reports)
# when picking up new `klt` capability.
#
# Bumped for issue #15 (bandgap-core floorplan): the prior pin
# (0cd630886e7b0034671d3e1e5d3131150596275f) only supports
# `gen-compose`'s `placement.strategy: "row"`, which cannot express a real
# two-dimensional floorplan (2AMLogic/klayout-tools#321). This pin adds
# `placement.strategy: "explicit"` (2AMLogic/klayout-tools#330) plus a
# `gen-compose` request-path fix (#328/#332) and byte-reproducible GDS2
# output (#325) -- all additive, no behavior change to the row strategy or
# to `gen`/`drc`/`extract`/`lvs`, confirmed by re-running
# layout/bin/run-trivial-cell-flow.sh unmodified after the bump (still
# PASS, identical verdict; see trivial-cell/reports/ for the refreshed
# record).
#
# Bumped for issue #62 (routed bandgap-core layout). The prior pin
# (67ae02ed6199c0d9c314771669fbbc925364587a) predates three capabilities this
# issue's flow depends on, all now merged upstream:
#
#   * `res_array`'s `rows` fold parameter (2AMLogic/klayout-tools#415, merged
#     via #418) -- the reason the #15 skeleton drew a reduced 16-unit R2A/R2B
#     ladder instead of the real 108. With folding, 108 units occupy ~1,231
#     um^2 instead of a ~710 um-long single row, and the real count fits the
#     area budget. This is what closes issue #62's acceptance criterion 2.
#   * the `diff_pair` nfet/pfet misclassification fix (#421, merged via #426)
#     -- before it, every `flavor: "nfet"` device was enclosed in the
#     guard-ring well tie and extracted as `pfet`. Verified effective at this
#     pin: an isolated nfet `diff_pair` now extracts `{"nfet": 8}`, and the
#     composed layout reports both flavours.
#   * the `res_array` resistor-ID marker fix (#369, merged via #382) -- a
#     drawn ladder now extracts as `res_generic_po` resistors rather than
#     plain interconnect.
#
# It also carries `klt gen-compose`'s two-pin routing, `connectivity[]` net
# labels and `pins[]` pin promotion, which is what lets the routed flow draw
# real inter-block metal and promote named top-level pins.
#
# Additive to everything the earlier flows use: re-running
# layout/bin/run-trivial-cell-flow.sh unmodified after the bump still PASSes
# with the identical verdict (see trivial-cell/reports/ for the refreshed
# record).
#
# Bumped again for issue #62's second increment (routed bandgap-core layout,
# intra-block bussing). The prior pin (680ee42edf2319aa944f66df1f6f7db3975a73c4,
# PR #64) predates three fixes this increment depends on, all now merged
# upstream and closed as friction issues #432/#433/#434 filed by PR #64:
#
#   * 2AMLogic/klayout-tools#440 (merged 11c3f2dbffeb362c895a65b424d0ce32c9621fbe)
#     -- `klt gen bjt_array` now draws its own per-unit bipolar
#     device-recognition marker + nwell tap on sky130, replacing the local
#     `klt draw` overlay workaround (PNP_OVERLAY_NOTE) this flow previously
#     carried for issue #432.
#   * 2AMLogic/klayout-tools#439 (merged ac10d834398724dd8174552046324aa13e947c22)
#     -- `gen-compose`'s self-net router now rejects (rather than silently
#     drawing as a certified short) a self-net backbone that crosses another
#     port's pad on the same block. This is a "fail visibly" safety net, not
#     new routing capability -- it does not by itself make intra-block
#     bussing routable; it only makes an unroutable bussing attempt report
#     `unrouted_nets[]` instead of a silent short. A self-net hop between two
#     ports that do NOT have a third pad between them (e.g. two immediately
#     physically adjacent unit ports) is unaffected and continues to route,
#     which is what this increment's chained-adjacent-hop bussing technique
#     (see gen_bandgap_routed.py's `bus_ports_chain`) exploits.
#   * 2AMLogic/klayout-tools#441 (merged 4fa8440687b1422d9a6fa1b25ed487935b3c1f67)
#     -- `klt gen`'s guard/collector ring generators now leave a routing
#     opening, so a block keeping its own guard ring is no longer
#     automatically unroutable. This lets this increment restore the
#     per-matched-group guard rings PR #64 had to drop (matching-plan.md
#     Section 5a).
#
