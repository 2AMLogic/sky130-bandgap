## Determination

**Reading 2 (a real electrical effect), confirmed.** Chaining 7 real `sky130_fd_pr__res_high_po` unit instances via ideal wires (R1's shape) measures +19.39% higher than one instance drawn at the same 35 um combined length; chaining 70 units (R2A/R2B's shape) measures +29.74% higher. Both numbers reproduce `klt`'s own LVS-extracted values to within 0.10% using an independent mechanism (real ngspice evaluation of the PDK's nonlinear `rhead`/`rbody` model cards through ideal interconnect, not `klt`'s own analytic extraction formula) -- so the gap 2AMLogic/klayout-tools#518/#519/#526 measures at LVS time is not an extractor bookkeeping artifact. The model card's own structure explains why: `rhead`'s width is a fixed function of `w` and its length is a hardcoded `l=1.0`, *independent of the caller's drawn body length* -- so a real device really does pay this term once per physically separate, individually-contacted instance, and `rbody`'s own `leff = l + 0.247` fringe term adds a further per-instance length markup. The routed layout's `bus_res_series` draws real contacts and metal risers at every one of the array's internal unit boundaries (issue #98's Problem section), which is exactly the structure this model term represents -- so real fabricated silicon built from this layout really does pay N times the head/fringe term, not once per logical divider leg.

K = R2/R1 shifts from 7.4973 (single-device model -- what `design/bandgap_core.sch` and every existing PVT sim record in this repo actually simulates today) to 8.1474 under the routed layout's real chained topology (+8.67%), because R1's delta (+19.39%) and R2A/R2B's delta (+29.74%) differ -- confirming the concern issue #98's Problem section raised: this is not a uniform scale factor on both resistors.

**Material.** Substituting the chained-array topology into the real core testbench (Phase B) pushes VOUT(27 degC) outside the draft +/-1% spec window (1.188-1.212 V) at 5/5 corner points: tt/3.30V, ss/3.30V, ff/2.97V, sf/2.97V, fs/2.97V. This is the same class of finding issue #46 (operating-point collapse from a +1.4% R2 error) and issue #91 (drawn-length mismatch) treated as real and actionable, not a rounding-level effect to wave off.
